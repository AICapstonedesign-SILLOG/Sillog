# Sillog

**흩어진 업무 기록을 연결하고, 필요한 순간에 다시 활용하는 macOS 앱.**

Sillog은 앱·문서·웹페이지에서의 활동을 기록해 업무와 지식 그래프로 정리합니다. 채팅에서는 내 기록과 선택한 자료를 함께 읽어 문서, 조사 결과, 계획 등의 결과물을 만들 수 있습니다.

## 주요 기능

| 화면 | 할 수 있는 일 |
| --- | --- |
| **그래프** | 업무·세션·자료·앱·주제의 관계를 탐색하고 관련 자료를 다시 열기 |
| **업무** | 업무별 시간과 세션 요약을 확인하고, 마지막에 사용한 파일·웹페이지·앱 다시 열기 |
| **파일** | 다운로드한 파일의 정리 위치를 제안받고, 승인 후 이동하거나 되돌리기 |
| **보관함** | 업로드한 파일·생성한 결과물·저장한 답변을 검색·미리보기·내보내기하고 프로젝트에서 재사용 |
| **활동 로그** | 수집한 원시 기록·화면 내용·스크린샷과 LLM 정리 결과 확인 |
| **채팅** | 내 기록과 연결한 자료를 검색하고, 근거가 붙은 답변과 파일 결과물 만들기 |
| **설정** | 수집 범위·제외 앱·보관 기간과 정리용·채팅용 LLM을 각각 설정 |

### 내 자료로 작업하는 채팅

- **여섯 스킬**: 문서 작성, 리서치, 기획·계획, 학습, 콘텐츠 제작, 작업 자동화. 직접 고르거나 자동 선택할 수 있습니다.
- **하위 에이전트**: 복잡한 요청은 활동 조사·코드 조사·외부 리서치·근거 검토에 역할을 나누어 맡길 수 있습니다.
- **근거 확인**: 답변의 출처 칩에서 실제 조회한 기록·파일·웹페이지를 확인합니다. 자료를 열었다는 기록과 작업 완료·개인 기여는 구분합니다.
- **결과물**: Markdown, HTML, CSV, JSON, TXT로 저장하고, 미리보기에서 PDF로 내보낼 수 있습니다.
- **대화 탐색**: 대화 이름 변경·삭제, 사이드바 너비 조절, 질문·답변 미리보기와 이동을 지원합니다.
- **프로젝트 제안**: 같은 목표의 업무·대화를 묶을 후보를 제안하고, 수락하면 프로젝트를 생성합니다. 프로젝트는 일반 채팅 위에 표시되며 항목을 다른 프로젝트로 옮길 수 있습니다.
- **예약 작업**: 반복 조사·요약을 제안받고 승인 후 등록합니다. 세부 내용 확인, 일시중지·재개·삭제가 가능합니다.

## 빠른 시작

### 준비 사항

- macOS 14 이상, Swift 5.10 이상
- Git과 Xcode 또는 Xcode Command Line Tools
- 온보딩용 ChatGPT 로그인 계정
- Codex 방식의 채팅을 사용할 경우 Codex 데스크톱 앱 또는 최신 Codex CLI

단위 테스트에는 `XCTest`를 제공하는 전체 Xcode 설치가 필요합니다. Command Line Tools만 설치한 환경에서도 앱 빌드는 가능합니다.

### 빌드 및 실행

```bash
git clone https://github.com/AICapstonedesign-silog/Sillog.git
cd Sillog
./scripts/make-app.sh
open build/Sillog.app
```

스크립트는 임시 빌드 폴더에서 Release 빌드, 앱 번들 생성, 코드 서명을 수행한 뒤 `~/Applications/Sillog.app`에 설치합니다. `build/Sillog.app`은 설치된 앱으로 연결되므로 실행과 macOS 권한 등록에는 같은 앱을 사용합니다.

### 첫 실행

1. **ChatGPT 로그인**: 브라우저에서 표시된 기기 코드를 입력합니다. 로그인 전에는 활동을 수집하지 않습니다.
2. **권한 선택**: 손쉬운 사용과 화면 기록을 허용합니다. 화면 기록 허용 후에는 앱을 다시 실행하세요. 권한이 없으면 앱 이름만 기록됩니다.
3. **수집 범위 확인**: 설정에서 화면 텍스트·스크린샷·AI 코딩 도구 대화 수집과 제외할 앱을 선택합니다.
4. **LLM 설정**: 정리에 쓰는 LLM과 채팅에 쓰는 LLM을 각각 선택하고 연결을 확인합니다.

ChatGPT 모델 선택창은 서버에서 받은 후보를 선택한 정리용·채팅용 연결에서 각각 확인한 뒤 실제 응답한 모델만 표시합니다. 앱 실행 후 첫 확인과 설정의 ‘모델 다시 확인’은 개인 자료 없이 테스트 요청을 보내며 모델 사용량이 소량 발생합니다. 지원하지 않는 기존 선택은 확인된 모델로 변경합니다. 일부 모델의 확인 실패는 성공한 목록과 함께 표시하며, 사용량·인증 오류가 나면 추가 요청을 멈춥니다. 검사 중에는 중단할 수 있고, 로그아웃하거나 연결 방식을 바꾸면 진행 중인 검사를 취소합니다.

앱은 Dock과 메뉴바에서 열 수 있습니다. 메뉴바에서 수집을 일시정지하거나 지금 정리를 실행할 수 있습니다.

> 다시 빌드할 때 권한을 유지하려면 같은 서명 인증서를 사용해야 합니다. 인증서 선택과 권한 문제 해결은 [개발 가이드](docs/development.md#빌드와-권한)를 참고하세요.

## 채팅 사용

1. 채팅 탭에서 **새 대화**를 엽니다.
2. 입력창의 **+**로 파일·폴더를 연결하고, **자료**에서 활동 기록·웹 검색·플러그인 사용 범위를 선택합니다.
3. 스킬을 고르거나 자동 선택 상태로 요청을 입력합니다. Enter는 전송, Shift+Enter는 줄바꿈입니다.
4. 답변의 출처 칩과 **참고 자료**에서 근거를 확인합니다. 결과물 카드를 누르면 미리보기·저장·PDF 내보내기를 할 수 있습니다.

**LLM 연결 방식**

- **Codex**: 앱의 ChatGPT 로그인으로 독립적인 App Server를 실행합니다. 설치된 Codex의 웹 검색을 사용하되, 사용자의 Codex 설정·MCP·플러그인은 공유하지 않습니다.
- **OpenAI 호환 서버**: 스트리밍과 도구 호출을 지원하는 모델·서버를 사용합니다. 공식 OpenAI API 연결은 Responses API의 `web_search`로 검색하며 **Tavily는 필요하지 않습니다.** 다른 호환 서버의 웹 검색은 지원하지 않습니다.

예약은 사용자가 제안을 확인하고 **등록**해야 실행됩니다. 앱이 실행 중일 때만 동작하며, 종료·절전 중 놓친 실행은 한 번 처리합니다. 결과는 별도 대화에 남습니다.

**프로젝트**는 앱 실행·업무 정리·채팅 완료 후 정리용 모델이 확인합니다. 처음에는 기존 업무·대화를 한 번씩 검토하고, 이후에는 새 항목만 판단합니다. 사이드바의 **제안**에서 이름과 묶을 항목을 확인한 뒤 **프로젝트 만들기**를 누르세요. 무시하거나 직접 옮긴 항목은 다시 자동 분류하지 않습니다. 프로젝트를 삭제해도 업무·대화·원본 파일은 남습니다.

사이드바의 프로젝트 제목 옆 **+**로 직접 만들 수 있습니다. 프로젝트 화면의 **채팅** 탭에서 대화를 보고 새 채팅을 시작하고, **소스** 탭에서 파일과 연결 폴더를 관리합니다. **프로젝트 설정**에서 목표·공통 지침·참고 범위를 수정하세요. 기본값인 **전체 기록 참고**는 현재 프로젝트를 우선하면서 다른 기록도 검색합니다. **프로젝트 전용**은 해당 프로젝트의 업무·대화·공용 자료만 참고하며, 일반 채팅과 다른 프로젝트에서도 그 기록을 읽지 못하도록 분리합니다.

**보관함**에 업로드한 파일은 DB 옆 `library/`에 복사합니다. 채팅의 **+**에서 **이 채팅에서만** 또는 **프로젝트 전체**로 추가하거나 기존 보관 자료를 선택하세요. 원본 파일·폴더 연결은 복사하지 않고 현재 원본을 읽는 기존 방식입니다. 한 대화의 전용 첨부는 같은 프로젝트의 다른 대화에 자동 공유하지 않습니다.

생성한 결과물은 기존 결과물을 포함해 보관함에 자동 보관합니다. 중요한 답변은 **프로젝트 자료로 저장**으로 남길 수 있습니다. 저장한 답변과 질문에 관련된 과거 기록 일부를 새 요청에 제공하고, 오래된 메시지와 결과물 본문도 검색·페이지 조회할 수 있습니다. 보관함에서 삭제한 결과물은 자동 수집으로 다시 만들지 않습니다.

## 개인정보와 데이터

**로컬 저장과 외부 전송은 별개입니다.** 기록은 로컬 SQLite에 저장되지만, LLM 정리와 채팅에 사용하는 내용은 설정된 모델 서버로 전송됩니다.

- **수집 제어**: 제외한 앱과 Sillog 자체는 앱 이름·시간만 남고 창 제목·URL·화면 내용·스크린샷은 기록하지 않습니다. 화면 내용 기록을 켜면 선택한 스크린샷이 LLM에 전송됩니다.
- **자료 접근**: 채팅은 대화에 연결한 자료, 기억 범위에서 허용된 프로젝트 공용 자료와 승인한 플러그인을 읽습니다. 기록에 경로가 나타났다는 이유만으로 원본 파일 접근을 허용하지 않습니다. 공통 지침과 관련 과거 기록·보관 자료 일부는 첫 요청부터 모델에 전달됩니다.
- **프로젝트 제안**: 업무 요약·대화 내용·연결 자료의 이름과 경로를 정리용 모델에 전송합니다. 분류는 제안을 수락한 뒤 반영합니다.
- **외부 검색**: 허용하면 검색어·조회 URL이 외부 서비스에 전달됩니다. 일반 연결 오류는 자동으로 재시도하지 않습니다.
- **읽기 중심**: 채팅은 임의 셸 실행, 메일 발송, 원본 문서·저장소 수정을 하지 않습니다. 다운로드 파일 이동은 별도 승인 후에만 수행합니다.
- **인증 정보**: 플러그인 토큰과 채팅 API 키는 macOS Keychain에 저장합니다. ChatGPT 로그인 토큰은 권한 `600`인 로컬 파일에 저장하며 Codex CLI의 인증 파일과 공유하지 않습니다.
- **대화 범위**: 자료 설정을 바꿔도 이전 메시지는 남습니다. 이전 자료가 없는 상태로 시작하려면 새 대화를 만드세요.

기존 사용자 데이터와 설정을 유지하기 위해 저장 경로, 번들 ID, Swift 모듈 이름과 `WORKGRAPH_*` 환경변수는 이전 이름을 유지합니다.

```text
~/Library/Application Support/WorkGraph/
├── workgraph.sqlite   # 활동·그래프·대화·결과물·예약
├── captures/          # 스크린샷
├── library/           # 보관 파일의 복사본·생성 결과물·저장한 답변
├── codex-auth.json    # 앱 전용 ChatGPT 인증
└── app.log            # 실행·권한·정리 상태 로그
```

## 개발

SwiftUI·AppKit을 사용한 네이티브 앱입니다. 수집은 접근성 API·ScreenCaptureKit·Vision·FSEvents, 저장은 SQLite·GRDB, 그래프 화면은 WKWebView와 force-graph를 사용합니다.

```text
Sources/
├── WorkGraphApp/          # 앱 상태, 화면, 플러그인 인증, 예약 실행
├── WorkGraphCollectors/   # macOS 활동·화면·파일·AI 대화 수집
├── WorkGraphCore/
│   ├── Chat/              # 검색, 모델 실행, 도구, 스킬, 결과물
│   ├── Ontology/          # 업무 배정, 그래프 반영, 세션·업무 병합
│   ├── Memory/            # 화면 기억 카드
│   ├── Storage/           # SQLite 저장·마이그레이션
│   └── LLM/               # ChatGPT 인증·OpenAI 호환 클라이언트
└── wgctl/                 # 개발·점검 CLI
Tests/WorkGraphCoreTests/   # 저장·분류·채팅·예약 회귀 테스트
```

```bash
swift build
swift test
swift run wgctl                       # CLI 도움말
swift run wgctl stats                 # 기록 통계
swift run wgctl rows --last 20 --text  # 최근 관측 행
```

- [개발 가이드](docs/development.md): 빌드·권한, 환경변수, 데이터 조회, 모델 없이 흐름 확인
- [플러그인 설정](docs/plugins.md): 공급자별 OAuth 설정과 배포 제한
- [설계 문서](docs/superpowers/specs): 수집·그래프·화면 기억 설계
- [스킬 지침](Sources/WorkGraphCore/Chat/Skills): 여섯 스킬의 작업 절차

변경은 작업 단위로 커밋하고, 기존 Swift 스타일을 따릅니다. 새 함수는 `Args`, `Returns`, `Raises`를 포함해 문서화하며 불필요한 검증·재시도·리팩터링을 추가하지 않습니다.

## 현재 제한사항

- **Office 형식**: 보관함에 업로드한 DOCX·PPTX·XLSX의 텍스트를 추출해 검색합니다. 네이티브 Office 파일 생성은 지원하지 않습니다. 슬라이드·다이어그램은 HTML 결과물과 PDF 내보내기를 활용할 수 있습니다.
- **보관 자료**: 파일은 50MB 이하이며 텍스트·PDF·Office 문서·이미지의 글자 인식을 지원합니다. 추출하지 못한 파일은 원본을 보관하고 제한을 표시합니다. 본문 추출은 최대 200만 자이며 이미지 자체의 시각적 해석은 지원하지 않습니다. 협업·클라우드 동기화는 지원하지 않습니다.
- **PDF 읽기**: 텍스트 추출을 지원하지만 스캔 PDF의 OCR은 지원하지 않습니다.
- **생성·실행 범위**: 이미지·영상 생성, 웹 게시, 임의 명령 실행은 지원하지 않습니다.
- **예약**: 시간 간격 기반이며, 요일·시각 지정 및 앱 종료 중 백그라운드 실행은 지원하지 않습니다.
- **계정 연결**: OAuth 등록과 실제 로그인 검증이 남아 있습니다. Notion 배포에는 서버 측 비밀키 처리도 필요합니다.
- **ChatGPT 연결**: 정리 기능은 공개 API가 아닌 Codex 백엔드를 사용하므로 규격 변경의 영향을 받을 수 있습니다. 공식 API 연결은 별도의 API 키와 사용 요금이 필요합니다.
- **플랫폼**: macOS만 지원합니다.
